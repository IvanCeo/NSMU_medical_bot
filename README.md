# Medical bot

Telegram-бот `@NSMU_medicial_bot` для учебной группы: задания, дедлайны,
отметки выполнения, напоминания и дайджесты.

Реализован MVP с группами, предметами, заданиями, вложениями, личными отметками,
напоминаниями и групповым дайджестом. Управление — через команды и кнопки Telegram.
Миграции применяются автоматически до запуска long polling.

## Требования

- Go **1.27.1**, версия закреплена в `go.mod`.
- GNU Make. Поддерживаются Windows (`cmd.exe`) и Linux/macOS (POSIX shell).
- Для `make test-race` нужен C-компилятор: например, GCC из MSYS2 UCRT64 в Windows.
- Сеть для первоначальной загрузки модулей и отсутствующих инструментов.
- Docker Engine/Desktop и Docker Compose v2 для контейнерного запуска.

Добавьте каталог установки Go-инструментов в `PATH`: обычно это
`%USERPROFILE%\go\bin` в Windows или `$(go env GOPATH)/bin` в Linux/macOS.
Если задан `GOBIN`, используйте его.

## Локальный запуск

```text
make setup
```

Команда создаёт `.env` из `.env.example`, сохраняя существующий `.env`,
загружает Go-модули и устанавливает отсутствующие `golangci-lint` и `goose`.
Для установки закреплены версии `v2.13.2` и `v3.26.0` соответственно;
уже доступные в `PATH` инструменты сохраняются. Версии установки можно
переопределить через `GOLANGCI_LINT_VERSION` и `GOOSE_VERSION` в команде Make.

Заполните `BOT_TOKEN` и `ADMIN_TELEGRAM_IDS` в `.env`, затем выполните:

```text
make run
```

Нужен действующий токен: приложение авторизуется в Telegram. Напишите `/start`
в личном чате. Администратор из конфигурации создаёт группу через `/admin`,
передаёт приглашение участникам и назначает редактора. Без учебных данных бот
показывает меню и пустые списки. Произвольный текст вне мастера вызывает подсказку.
Для остановки нажмите `Ctrl+C`: polling, фоновые задачи и HTTP-запросы отменяются,
затем закрывается БД.

Каталог для `DB_PATH` создаётся автоматически. Ошибки конфигурации, открытия
БД, миграций или авторизации завершают запуск с ненулевым кодом. Временные
сетевые ошибки polling повторяются с задержкой. Фоновые отправки сохраняются
в очереди SQLite и повторяются после временных ошибок. При аварии между
принятием сообщения Telegram и подтверждением в БД возможен дубль.

Не запускайте несколько экземпляров с одним токеном. Если для бота уже
настроен webhook, сначала осознанно переключите его на polling: приложение
не удаляет webhook и ожидающие обновления автоматически. Ошибка 409
останавливает приложение.

## Запуск через Docker

После заполнения `.env`:

```text
make docker-check
make docker-up
make docker-logs
```

Compose собирает один контейнер бота. SQLite работает в нём, а файл
`/data/bot.db` и его WAL хранятся в именованном volume `bot_data`
(Docker добавляет префикс имени Compose-проекта). В контейнере DB_PATH
переопределён на этот путь; локальное значение из `.env` сохраняется для
`make run`. Входящие порты не нужны. Бинарник работает от пользователя
`65532:65532`; корневые TLS-сертификаты включены в runtime-образ.

```text
make docker-down
```

Остановка и повторное создание контейнера сохраняют volume. Локальный файл
`./data/bot.db` и база в Docker volume — разные хранилища. Токен передаётся
при запуске, `.env` не попадает в образ. Команда проверки Compose не выводит
раскрытые значения конфигурации.

Этот Compose предназначен для локальной сборки и запуска. Существующая
целевая схема продакшена с образом из реестра описана в ARCHITECTURE.md.

## Конфигурация

Образец всех ключей — `.env.example`. Приложение читает `.env` из текущего
рабочего каталога. Переменные окружения имеют приоритет, включая явно пустые
значения. Отсутствие файла допустимо при настройке через окружение. Само
окружение процесса при загрузке не изменяется. Пробелы по краям значений
удаляются. Поддерживаются комментарии, кавычки и UTF-8 с BOM.

| Ключ | Обязателен / значение по умолчанию | Проверка |
| --- | --- | --- |
| `BOT_TOKEN` | Обязателен | Непустое значение; авторизация в Telegram при запуске |
| `ADMIN_TELEGRAM_IDS` | Обязателен для бота | Уникальные положительные int64 Telegram ID через запятую; `@username` не подходит |
| `DB_PATH` | Обязателен | Непустой путь; локальный пример — `./data/bot.db` |
| `TZ` | `Europe/Moscow` | IANA-зона или `UTC`; значение `Local` запрещено |
| `DIGEST_TIME` | `08:00` | Строго `HH:MM`, от `00:00` до `23:59` в зоне `TZ` |
| `REMINDER_OFFSETS` | `24h,3h` | Положительные Go duration через запятую, например `24h,3h,30m`; `1d` не поддерживается |
| `LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error` |
| `ENV` | `dev` | `dev` — текстовые логи; `prod` — JSON |

Значения по умолчанию применяются только к отсутствующим ключам. Пустые
значения проверяются и вызывают ошибку. Неизвестные ключи игнорируются.
Ошибочный синтаксис существующего `.env` блокирует запуск даже при полном
наборе переменных окружения. Содержимое строк файла в ошибки не включается.
Часовые пояса встроены в бинарник и доступны без системной базы zoneinfo.

`.env`, локальные базы данных и результаты сборки исключены из Git. Реальные
токены храните в `.env` или окружении; в `.env.example` поле токена оставлено пустым.

## Администраторы и миграции

Задайте в `ADMIN_TELEGRAM_IDS` числовые ID администраторов. При старте после
миграций используются ID их личных аккаунтов, а не ID бота из начала токена. Эти
записи атомарно создаются или получают роль `admin`.
До первого сообщения имя может быть пустым. Повторный запуск и обновление
имени сохраняют группу и исходную дату регистрации.

Список является источником прав: исключённые ID при следующем запуске
получают роль `student`. Редакторы вне списка не меняются. Синхронизация
выполняется одной транзакцией, поэтому ошибка не оставляет часть прав изменённой.
Реальные ID в пример конфигурации не включены.

Миграции можно применить отдельно:

```text
make migrate
```

Команда читает только `DB_PATH` из `.env` или окружения и допускает повторный
запуск. Токен и список администраторов не требуются; роли не синхронизируются.
Путь можно переопределить: `make migrate DB_PATH=./data/other.db`.
Миграции встроены в бинарник и содержат обе секции goose Up/Down.

Подробная схема: [docs/database.md](docs/database.md).

## Как пользоваться

1. Администратор: `/admin` → «Создать группу». Название и код приглашения
   появляются в панели группы. Участник пишет `/join <код>` либо открывает
   `https://t.me/<имя_бота>?start=join_<код>`.
2. Администратор создаёт предметы в панели группы, затем через «Участники и
   редакторы» назначает старосту редактором. Редактор может сам управлять
   предметами: `/subjects manage`.
3. Редактор: `/add` → предмет → вид → название → описание → будущий срок
   `ДД.ММ.ГГГГ ЧЧ:ММ` в `TZ` → важность → ссылка → документы/фотографии →
   «Готово» → предварительный просмотр → подтверждение. Для пустых описания,
   ссылки и преподавателя вводится `-`. До подтверждения задание остаётся черновиком.
4. Студент: `/tasks` → период → карточка. «Выполнено» и «Снять отметку» меняют
   только собственную отметку. «Напомнить через 3 часа» доступно до срока.
5. Администратор добавляет бота в учебный чат, назначает его администратором
   и отправляет в этом чате `/bind <ID учебной группы>`. Отправитель также
   должен быть администратором Telegram-чата. В группе появляется только дайджест.

| Команда | Назначение |
| --- | --- |
| `/start`, `/help`, `/profile` | Меню, справка, профиль и роль |
| `/join [код]`, `/leave` | Вступление и подтверждение выхода |
| `/tasks [day/week/all/overdue] [all/pending/done]` | Период и личный фильтр выполнения |
| `/subjects` | Предметы и переход к заданиям |
| `/settings` | Личные напоминания и тихие часы |
| `/add`, `/edit [ID]`, `/cancel_task [ID]` | Создание, изменение и отмена задания редактором или администратором |
| `/subjects manage` | Создание, изменение, архивирование и восстановление предметов |
| `/admin` | Группы, приглашения, редакторы, участники, предметы, дайджест и журнал |
| `/bind ID` | Привязка чата; выполняется в группе Telegram |
| `/cancel` | Отмена текущего мастера |

Администратор может указать группу явно: `/tasks 12 all pending`, `/subjects 12`.
Ему не нужно вступать в неё. В мастере `/add` группа выбирается кнопкой.
Длинные списки с явной группой/фильтром выполнения выводятся несколькими
сообщениями; обычный список заданий имеет кнопку следующей страницы.

Участник состоит в одной группе; для перехода сначала требуется выход.
Редактору перед выходом администратор снимает роль. Приглашение можно заменить
в `/admin`; прежний код перестанет работать. Удаление задания означает отмену:
история, вложения и отметки сохраняются. Архивный предмет скрывается из нового
мастера. Редактирование проверяет версию: старая карточка предлагает обновление.
Один активный мастер на пользователя сохраняется в SQLite на 30 минут с
последнего шага и переживает перезапуск; новая команда мастера заменяет прежний.

## Автоматические задачи

Внутри процесса работают планирование раз в 15 секунд, обработчик очереди
и завершение просроченных мастеров раз в минуту. Отдельного cron-контейнера нет.

- `REMINDER_OFFSETS` задаёт личные интервалы до дедлайна. Планируются только
  будущие интервалы; при вступлении/включении напоминаний прошедшие не рассылаются.
  Накопившиеся за простой интервалы объединяются до одного актуального.
- Выполнение задания, выход, отмена или выключение напоминаний отменяют
  ожидающие личные отправки. Snooze заменяет ближайшие, сохраняя последующие.
- Тихие часы задаются в `/settings` в `TZ`, в том числе через полночь. Отправка
  переносится на конец интервала; после дедлайна напоминание не отправляется.
- `DIGEST_TIME` — ежедневный дайджест заданий на текущую дату по `TZ`.
  Пустой дайджест не отправляется. После простоя догоняется только сегодняшний.
  Части длинного дайджеста подтверждаются отдельно. Перепривязка чата отменяет
  ожидающие части и не повторяет уже запланированный сегодня дайджест.
- Очередь хранит до 5 попыток, задержки 15/30/60/120 секунд с учётом `retry_after`.
  Захват записи действует 2 минуты. После блокировки бота личные отправки
  прекращаются до нового личного обращения пользователя.
- Общий лимит: 20 сообщений/с, один личный чат — раз в секунду, группа — раз
  в 3,1 секунды. Уже принятый Telegram запрос нельзя гарантированно отозвать.

## Команды разработки

| Команда | Действие |
| --- | --- |
| `make setup` | Подготовить `.env`, инструменты и модули |
| `make env` | Создать `.env`, если его ещё нет |
| `make tools` | Установить отсутствующие инструменты |
| `make run` | Запустить приложение из исходников |
| `make test` | Запустить все тесты |
| `make test-race` | Запустить тесты с детектором гонок |
| `make test-coverage` | Совокупное покрытие сервисов unit- и интеграционными тестами; отчёт `coverage.out`, минимум — 70% |
| `make fmt` | Отформатировать Go-код |
| `make lint` | Отформатировать код, выполнить `go vet` и `golangci-lint` |
| `make build` | Собрать бинарник с `CGO_ENABLED=0` в `bin/bot` или `bin/bot.exe` |
| `make migrate` | Применить embedded-миграции к локальной БД из DB_PATH |
| `make docker-check` | Проверить Compose без вывода значений окружения |
| `make docker-build` | Собрать локальный Docker-образ |
| `make docker-up` | Собрать и запустить контейнер |
| `make docker-down` | Остановить контейнер, сохранив volume |
| `make docker-logs` | Следить за журналом контейнера |

Путь результата сборки переопределяется через `BIN`, команда Go — через `GO`.
Бинарник запускайте из корня проекта, чтобы он нашёл локальный `.env`.

## Устройство проекта

- `cmd/bot` — загрузка конфигурации, логгер и жизненный цикл процесса.
- `cmd/migrate` — отдельное применение миграций без подключения к Telegram.
- `internal/bot` — Telegram, polling, обработка сообщений и безопасные ошибки API.
- `internal/service` — регистрация, права, учебные сценарии, мастера и доставка.
- `internal/config` — конфигурация и её проверки.
- `internal/domain` — сущности и ошибки предметной области.
- `internal/repository/sqlite` — SQLite, миграции, репозитории и общая транзакция.
- `internal/scheduler` — планирование, очередь отправки и очистка мастеров.
- `migrations` — SQL-схема, встроенная через embed.FS.
- `ARCHITECTURE.md` — реализованная архитектура и границы MVP.
- `docs/adr` — шаблон архитектурного решения; упомянутые в архитектуре
  ADR-0001–0006 ещё не оформлены отдельными файлами; ADR-0007 описывает bootstrap,
  ADR-0008 — мастера, права и надёжную доставку.

Правила работы агентов и этапы согласования находятся в `AGENTS.md`.

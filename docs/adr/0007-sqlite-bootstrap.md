# 0007 — SQLite, миграции и начальные администраторы

- Status: Accepted
- Date: 2026-10-25

## Context

Для первого рабочего запуска нужны постоянное хранилище, повторяемые миграции
и начальные администраторы. Пользователь выбрал SQLite внутри контейнера бота
с постоянным Docker volume. Предыдущие инструкции требовали пары `.up.sql` /
`.down.sql`, хотя штатный goose использует секции Up/Down внутри одного файла.
Настройка goose через package-level функции также противоречит требованию
обходиться без изменяемого глобального состояния приложения.

## Decision

Используем `modernc.org/sqlite`, embedded SQL-миграции в стандартном формате
goose и экземпляр `goose.Provider`; администраторов синхронизируем из конфигурации.

- Каждый `NNNN_name.sql` содержит секции `-- +goose Up` и `-- +goose Down`.
- Миграции встраиваются в бинарник через `embed.FS`; Provider отключает
  глобальный реестр Go-миграций и применяет Up до запуска Telegram polling.
- SQLite работает в процессе бота. Compose монтирует `bot_data` в `/data`;
  `DB_PATH` внутри контейнера — `/data/bot.db`.
- Для каждого соединения включаются WAL, foreign_keys и busy_timeout=5000 мс.
  Пул ограничен одним соединением.
- `ADMIN_TELEGRAM_IDS` обязателен для бота: уникальные положительные int64 ID,
  разделённые запятыми. Имена пользователей не используются для выдачи прав.
- Синхронизация в одной транзакции создаёт отсутствующих администраторов
  с пустым именем и повышает указанных пользователей до admin. Администраторы,
  удалённые из конфигурации, становятся student. Редакторы вне списка не меняются.
- Повторная синхронизация сохраняет имя, группу и исходное время регистрации.
- Команда миграций требует только DB_PATH и не меняет роли.

## Consequences

- Positive: один контейнер, сохраняемые данные, миграции без внешних SQL-файлов,
  предсказуемые начальные права и тестируемые экземпляры зависимостей.
- Negative: один активный polling-процесс; SQLite предполагает локальный диск.
  Изменения списка администраторов вступают в силу после перезапуска.
  Удаление бывшего редактора из списка администраторов даёт роль student;
  история предыдущих ролей на этом этапе не хранится.

# Проверка исправления snooze и навигации

Дата: 25.10.2026. Ветка: `chore`.
Основание: [утверждённый план](2026-10-25-snooze-navigation.md).

## Причина ошибки

Snooze успешно сохранял напоминание, затем пытался изменить карточку на тот же
текст и кнопки. Telegram 400 message is not modified превращался в общую
временную ошибку. Deferred answerCallbackQuery заменял исходную ошибку своим
результатом; при успешном ответе в цикл polling приходил nil, поэтому лог был пуст.

Перед исправлением регрессионные тесты воспроизвели лишнее редактирование,
неверную классификацию no-op и потерю исходной ошибки. После исправления проходят.

## Изменения

- Snooze подтверждается уведомлением «Напомню через 3 часа; тихие часы учитываются»
  без повторной записи неизменённой карточки. Интеграция проверяет наличие
  сохранённого snooze в SQLite после нажатия.
- Известный message-is-not-modified только при edit считается успехом.
  Другие 400 и 403 не подавляются; причина кодируется безопасным enum.
- Обработчик и answer имеют независимые callback_failed/callback_answer_failed.
  В логах действие, Telegram ID, категория/тип, Telegram/SQLite code при наличии.
  Исходные ошибки и URL с токеном не печатаются. Fatal answer тоже не раскрывает
  посторонние детали ошибки обработчика через logger запуска.
- Навигация по кнопкам повторно использует исходный message ID. Только первая
  часть использует его; продолжения и файлы не затирают этот экран.
- Edit явно отправляет актуальную клавиатуру, включая пустой массив для её
  удаления; превью ссылок остаётся выключенным. Неизвестная ошибка редактирования
  не скрывается, для недоступного сообщения допускается новое.
- Карточка содержит «Задания предмета» с существующим subject callback.
  Экраны содержат /start, мастера — /cancel. Обычный /start отменяет текущий мастер,
  чтобы текст после возврата к меню не применялся к скрытому незавершённому шагу.
- Неудавшееся действие не заменяет исходную рабочую карточку сообщением ошибки.
  Нет нового состояния между update, таблиц, env-ключей или callback-форматов.

Новые проверки: snooze без edit и с сохранением в БД; handler error + успешный
answer; успешный handler + сбой answer; одновременные сбои; безопасные логи;
edit-no-op против других ошибок; явное удаление клавиатуры; тот же message ID
для menu/tasks/subject/view/profile/settings/dialog; новая revision клавиатуры;
несколько частей карточки; недоступное исходное сообщение; сохранение исходной
карточки при отказе; выход из мастера через /start.

## Review и границы проверки

Lead проверил изменения по утверждённому плану. Сервисный слой, права и схема
БД сохранены; изменения находятся в transport и документации. Добавлен ADR-0009.
Старые клавиатуры прежних сообщений остаются защищены проверкой revision;
история сообщений и пользовательские ответы автоматически не удаляются.

Автоматические тесты не пропускались. Проверка с настоящим Telegram-токеном,
запуск/перезапуск контейнеров и публикация Docker-образа не выполнялись: тесты
используют fake API и временную SQLite; AGENTS.md запрещает агенту deployment
и изменение production-данных. Docker packaging в этом исправлении не менялся;
повторная сборка образа не выполнялась. Пользовательский .env и рабочая БД
не изменялись. Коммит, push и merge не выполнялись.

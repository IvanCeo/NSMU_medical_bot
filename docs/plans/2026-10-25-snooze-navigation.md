# Исправление snooze, логов и навигации Telegram

Статус: весь план утверждён пользователем 25.10.2026; реализация и проверки завершены.
Ветка: `chore`.

Результат: [отчёт проверки](2026-10-25-snooze-navigation-verification.md).

## Диагноз по коду

После успешного Snooze callbackDone повторно отображает ту же карточку через
editMessageText, хотя её текст и клавиатура не изменились. Ответ Telegram
400 message is not modified сейчас преобразуется в общую временную ошибку.
Это вероятное объяснение наблюдаемого поведения; воспроизведение через fake
Telegram API должно подтвердить его перед исправлением.

Воспроизведение подтвердило диагноз: регрессионные тесты до исправления
зафиксировали лишний edit, общую временную ошибку на edit-no-op и потерю
ошибки обработчика при успешном answer.

В callback отложенный answerCallbackQuery перезаписывает исходную ошибку
результатом отправки ответа. При успешном answer ошибка теряется и Bot.Run
не пишет reply_failed. respondError отдельно пишет только ErrStorage и
не включает диагностическую причину.

## Контракты

Сигнатуры сервисов, UI.Show/Answer, БД, миграции, env и форматы callback_data
сохраняются. Новое навигационное состояние между обновлениями не хранится.
Токены, URL API, тексты сообщений и коды приглашений в лог не добавляются.

Изменения поведения сообщений:

- Успешный snooze отвечает коротким callback-уведомлением «Напомню через
  3 часа; тихие часы учитываются», не редактируя неизменившуюся карточку.
- Точное известное сообщение Telegram «message is not modified» при
  редактировании считается успешным; остальные ошибки 400 сохраняются.
- Ошибка обработчика и ошибка answerCallbackQuery учитываются независимо.
  Неожиданные сбои получают безопасную диагностическую запись с действием,
  ID пользователя/объекта при наличии, типом ошибки и кодом Telegram.
  Ожидаемые ошибки доступа, ввода и устаревших кнопок не становятся ERROR.
- Callback-переходы обновляют исходное сообщение вместо отправки нового.
  Дополнительные части длинного текста и файлы остаются отдельными сообщениями.
  Неудавшееся действие сохраняет исходную карточку и её рабочие кнопки.
- Мастер заменяет клавиатуру на кнопки актуальной revision. Старые кнопки
  прежних сообщений по-прежнему защищены существующей проверкой revision.
- В карточке задания можно вернуться к заданиям предмета существующим
  subject:<ID>:0. В остальных разделах добавляется понятная подсказка
  «/start — главное меню», в мастерах также «/cancel — отмена».
- История сообщений и пользовательские сообщения автоматически не удаляются.
  Для улучшения UX достаточно редактирования и замены клавиатур.

## План

1. Воспроизвести snooze с Telegram 400 message is not modified и потерю логов.
2. Исправить подтверждение snooze, классификацию edit-no-op и учёт ошибок callback.
3. Повторно использовать исходное сообщение в callback-переходах; сохранить
   отдельные сообщения для файлов и продолжений длинного текста.
4. Добавить простой возврат и подсказки без новой схемы/навигационного стека.
5. Обновить тесты и документацию, выполнить тесты, race detector, lint и build.

## Приёмка

- Кнопка snooze создаёт ожидающее напоминание, получает подтверждение и не
  показывает временную ошибку из-за неизменённой карточки.
- Ошибки Telegram/БД в callback диагностируются даже после успешного answer;
  сбой самого answer тоже виден. Логи не раскрывают секреты и тексты сообщений.
- Переходы меню → список → карточка → список и шаги по inline-кнопкам используют
  ID исходного сообщения; нет новых копий на каждом нажатии.
- После шага мастера прежняя клавиатура заменена, устаревшие revision отклоняются.
- Ошибка доступа/ввода не лишает пользователя действующей карточки.
- Длинные сообщения и вложения доступны полностью; отдельные части не затирают
  друг друга. Есть возврат или /start, без новой таблицы/стека навигации.
- Рабочий контейнер, .env, пользовательская БД, публикация образа и deployment
  остаются вне изменений агента.

Вариант ограниченного объёма: выполнить только пункты 1–2 и относящиеся к ним
проверки из пункта 5, если пользователь выберет только bugfix.

# Проверка Docker, SQLite и эхо-бота

Дата: 2026-10-25. Ветка: `chore`.

## Выполнено

- `make lint`: gofmt, go vet, golangci-lint — без ошибок.
- `make test` и `make test-race`: проходят.
- `make test-coverage`: internal/service — 100% statements.
- `make build`: Windows amd64, CGO_ENABLED=0.
- `make migrate` дважды на отдельном тестовом пути, без BOT_TOKEN и
  ADMIN_TELEGRAM_IDS: успешно.
- `make docker-check`: Compose проверен без вывода переменных окружения.
- `make docker-build`: Linux amd64 образ собран локально, runtime — distroless
  static-debian13, UID/GID 65532:65532.

## Функциональные проверки

- Новый SQLite-файл, повторное открытие, WAL и PRAGMA на новых соединениях.
- Embedded-миграции Up, повторный Up, Down/Up на временных тестовых файлах.
- Ограничения FK/CHECK/UNIQUE, UTC-время и сохранение даты, роли и группы
  при обновлении имени пользователя.
- Создание начальных администраторов, повторный seed, отзыв прав удалённых
  из конфигурации ID, сохранение независимого editor, атомарный rollback
  при ошибке seed.
- `/start`, адресованная команда, точное эхо, игнорируемые сообщения,
  безопасный ответ при ошибке сервиса, продвижение offset, ошибки API
  401/409/429 и отмена HTTP long polling.
- Полный путь fake Telegram API → transport → service → SQLite → эхо.
  Во всех тестах используются только искусственные пользователи.

## Проверка Docker volume

Два изолированных контейнера одного образа последовательно подключались
к одному отдельному тестовому именованному volume. Сеть была отключена,
токен — тестовый. Оба запуска успешно создали/открыли БД, применили миграции
и синхронизировали администраторов, затем завершились на ожидаемой
недоступности Telegram. Ошибка не раскрыла токен.

Первый запуск создал пользователя 1 с ролью admin. Второй запуск с другим
списком администраторов сохранил его запись и исходную дату, понизил до student
и создал пользователя 2 с ролью admin. Снимки БД из контейнеров проверены
отдельным чтением. Фактическая версия SQLite — 3.54.1.

Тестовые контейнеры удалены, volume
`medical-bot-smoke-db-4ae0e105c5` сохранён согласно плану сохранения volumes.
Рабочий Compose volume и пользовательская БД не использовались.

сообщения в настоящий Telegram. Транспорт проверен через локальный fake API.

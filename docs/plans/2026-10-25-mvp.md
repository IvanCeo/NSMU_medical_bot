# Полный MVP: команды Telegram и фоновые задачи

Статус: план и контракт утверждены пользователем 25.10.2026; реализация и проверки завершены.
Ветка: `chore`.

Результаты: [отчёт о проверке](2026-10-25-mvp-verification.md).

## Подтверждённые пользователем решения

- Интерфейс MVP — команды и кнопки Telegram.
- Напоминания участникам отправляются в личные сообщения.
- В чат учебной группы автоматически отправляется только ежедневный дайджест.
- Сохраняются Go, SQLite, встроенные goose-миграции и один контейнер бота.

Сигнатуры сервисных и репозиторных интерфейсов:
[контракт MVP](../contracts/mvp.md).

## Пользовательские сценарии

### Регистрация и участие в группе

`/start` создаёт/обновляет пользователя и показывает меню. До вступления
доступны помощь, профиль и кнопка «Вступить в группу». Код приглашения вводится
в личном диалоге; также поддерживается `/start join_<код>`.

Успешное вступление устанавливает group_id и показывает название группы,
роль, состояние личных напоминаний и основное меню. Повторное вступление
в ту же группу идемпотентно. Одна учётная запись состоит в одной учебной группе.
Для перехода студент сначала выходит из предыдущей группы с подтверждением.
История отметок сохраняется, ожидающие личные уведомления прежней группы отменяются.

Редактор не может сменить/покинуть группу, пока администратор явно не снимет
его полномочия. Роль admin глобальна и сохраняется при смене членства.
Текущая синхронизация ADMIN_TELEGRAM_IDS при старте не изменяется этим этапом.
Администраторы назначаются только из конфигурации; через меню назначается
или снимается только роль editor.

### Команды и меню

Основные действия доступны кнопками; команды служат точками входа и короткими
путями. Параметры, не указанные в команде, запрашиваются пошагово.

| Команда | Доступ | Поведение |
| --- | --- | --- |
| `/start` | Все, лично | Регистрация, вступление по deep link, меню |
| `/help` | Все | Справка с учётом роли и контекста |
| `/profile` | Все, лично | Telegram ID, имя, роль, группа, уведомления |
| `/join [код]` | Все, лично | Пошаговое вступление или код аргументом |
| `/leave` | Участник, лично | Подтверждение выхода; ограничения для editor описаны выше |
| `/tasks` | Участник, лично | «Сегодня», «7 дней», «Все активные», «Просроченные», фильтры и страницы |
| `/subjects` | Участник, лично | Предметы своей группы и переход к заданиям |
| `/settings` | Все, лично | Личные напоминания и тихие часы |
| `/add` | Editor своей группы / admin, лично | Мастер создания задания |
| `/edit [ID]` | Editor своей группы / admin, лично | Выбор задания и мастер редактирования |
| `/cancel_task [ID]` | Editor своей группы / admin, лично | Подтверждение отмены задания |
| `/admin` | Admin, лично | Группы, приглашения, участники, редакторы, предметы, предварительный просмотр дайджеста, журнал |
| `/bind <ID группы>` | Admin, в групповом чате | Привязка чата после проверки прав Telegram |
| `/cancel` | Все, лично | Отмена своего текущего диалога |

В меню редактора доступны добавление и изменение предмета, его архивирование,
создание и изменение заданий. Администратор получает те же действия для
выбранной группы, а также создание/переименование группы, ротацию приглашения,
включение/выключение ежедневного дайджеста и управление редакторами.

Произвольный текст вне активного диалога показывает подсказку навигации.
Диагностическое эхо перестаёт быть основным поведением.

### Предметы и задания

Предмет принадлежит группе. Имя уникально среди активных предметов группы
после удаления пробелов по краям; регистр сохраняется. Архивирование предмета
скрывает его из выбора новых заданий, существующие задания сохраняются.

Мастер задания: предмет → вид → заголовок → описание → дедлайн → важность →
ссылка → вложения → предварительный просмотр → публикация.

- Виды: homework/test/exam/practice/other.
- Важность: low/normal/high; по умолчанию normal. Она влияет на обозначение
  в списке, но не меняет интервалы напоминаний.
- Заголовок: 1–200 символов; описание: до 3000; ссылка: только http/https,
  до 2048 символов. Описание, ссылка и вложения необязательны.
- Дедлайн вводится как ДД.ММ.ГГГГ ЧЧ:ММ в TZ. Для нового задания или изменения
  дедлайна требуется будущее время. Неоднозначное/несуществующее локальное
  время при смене часового пояса отклоняется с просьбой выбрать другое.
- До 10 вложений: документы или фотографии. Сохраняются file_id, тип,
  имя и MIME; файлы не скачиваются на сервер.
- Карточка показывает ID, предмет, вид, важность, название, описание, срок,
  статус, ссылку и кнопки. Длинный текст разбивается по лимитам Telegram.
- Публикация создаёт запись и будущие личные напоминания в одной транзакции.
  Массовой рассылки карточки при создании и отдельного поста в группу нет.
- Изменение увеличивает version. Сохранение с устаревшей version отклоняется.
- Отмена меняет status на cancelled и отменяет ожидающие отправки; историю,
  вложения и отметки физически не удаляет.

Карточки доступны по запросу и из напоминания. В личной карточке пользователь
может поставить/снять отметку выполнения и отложить напоминание на 3 часа,
если новое время раньше дедлайна. Отметки принадлежат конкретному пользователю.
Повторная установка/снятие отметки идемпотентны. Изменение отметки обновляет только его
личную карточку; общей отметки «вся группа выполнила» не существует.

### Права и изоляция

- Student читает данные текущей группы, меняет только свои отметки и настройки.
- Editor управляет предметами и заданиями своей группы.
- Admin управляет всеми группами и редакторами; группа для админского действия
  выбирается явно и передаётся сервису.
- Проверка выполняется сервисом при каждом действии, включая callback.
  Скрытая кнопка не заменяет проверку доступа.
- Нельзя создать задание с предметом другой группы; это также защищено FK.
- Нельзя получить чужие данные подстановкой ID или курсора списка.
- Снятие editor не даёт ему завершить ранее открытый мастер изменения.
- Привязка допускается только для group/supergroup: актор — admin бота и
  администратор чата Telegram; сам бот должен иметь права администратора чата.
  Один чат соответствует одной учебной группе. Автоматического закрепления
  дайджеста в этом этапе нет.

## Callback и состояние диалогов

Полный набор действий и аргументов закрыт контрактом:

| Формат | Назначение |
| --- | --- |
| `menu:<раздел>` | Раздел меню: tasks/subjects/profile/settings/admin/join |
| `tasks:<фильтр>:<курсор>` | Страница списка; фильтр day/week/all/overdue |
| `subject:<ID>:<курсор>` | Задания предмета |
| `view:<ID>` | Актуальная карточка задания |
| `done:<ID>:<version>` | Своя отметка выполнения |
| `undo:<ID>:<version>` | Снять свою отметку |
| `snooze:<ID>:<version>:3h` | Личное напоминание через 3 часа |
| `dlg:<ID>:<revision>:<значение>` | Выбор в текущем пошаговом диалоге |

Курсор — ограниченная строка base64url с ключом сортировки; пустой курсор
обозначается `0`. Он не определяет права доступа. Значения dlg — только
согласованные enum либо числовые ID; произвольный пользовательский текст
в callback не передаётся. Каждый payload — не более 64 байт.

Callback всегда получает answerCallbackQuery. Некорректные, чужие и просроченные
действия дают понятный ответ без изменения состояния. Устаревшая version
предлагает обновить карточку. Проверяется также владелец диалога и revision.

Один активный личный диалог на пользователя хранится в SQLite и переживает
перезапуск. TTL — 30 минут с последнего шага. Продолжение использует CAS по
revision. Сохраняются только поля создаваемого учебного объекта, а не исходные
обновления Telegram. После истечения показывается предложение начать заново.
Новый диалог всегда получает новый ID. Завершённые, отменённые и истёкшие
диалоги имеют отдельный status; их payload очищается. Это исключает применение
старой кнопки к новому мастеру даже при совпадении номера шага.

## Фоновые задачи

Используется internal/scheduler внутри процесса Go. Отдельный контейнер cron,
системный crontab и внешний брокер не добавляются.

| Задача | Когда | Результат |
| --- | --- | --- |
| Планирование уведомлений | При старте и раз в 15 секунд | Обнаружить наступившие напоминания и сегодняшний дайджест; создать записи outbox |
| Доставка outbox | Постоянный обработчик; пауза до 1 секунды при пустой очереди | Захватить одну запись, отправить, зафиксировать результат или повтор |
| Завершение просроченных диалогов | При старте и раз в минуту | Пометить истёкшие диалоги; больше не принимать их кнопки |
| Восстановление после сбоя | При старте и в обработчике доставки | Повторно взять запись после истечения lease; прекратить устаревшие уведомления |

Все циклы останавливаются через context. Время, интервалы и генерация токенов
инъецируются для тестов. Транзакции БД не удерживаются во время Telegram API.

### Личные напоминания

- Включены по умолчанию для участника, начавшего личный диалог с ботом.
- Интервалы — REMINDER_OFFSETS; уже прошедшие интервалы при создании задания
  не отправляются немедленно.
- При вступлении и включении уведомлений планируются только будущие интервалы
  активных незавершённых заданий текущей группы.
- При изменении дедлайна старые ожидающие отправки отменяются, новые получают
  актуальную version задания. Изменение текста тоже обновляет version и
  перепланирует оставшиеся интервалы.
- Отметка выполнения, выход из группы, выключение уведомлений или отмена
  задания отменяют ожидающие личные отправки. Снятие отметки планирует будущие.
- Тихие часы по умолчанию выключены. Пользователь задаёт интервал HH:MM–HH:MM
  в TZ, включая интервал через полночь. Отправка переносится на его конец;
  если это уже не раньше дедлайна, напоминание пропускается.
- После простоя due-запись отправляется, только если дедлайн ещё впереди.
  Несколько накопившихся стандартных интервалов одного задания одному человеку
  объединяются: отправляется только наиболее поздний наступивший интервал.
- Snooze заменяет ожидающие личные напоминания этого задания до выбранного
  времени; последующие стандартные интервалы сохраняются. Тихие часы действуют.
- Перед отправкой заново проверяются членство, настройки, отметка, статус и
  version. Изменение, совпавшее с уже выполняющимся HTTP-запросом, не позволяет
  гарантированно отозвать сообщение, принятое Telegram.

### Дайджест группы

- Планируется для привязанного чата в DIGEST_TIME по TZ, если включён для группы.
- Содержит активные задания с дедлайном в текущем местном календарном дне,
  отсортированные по сроку и ID; персональные отметки в группу не публикуются.
- Пустой дайджест не отправляется; результат «пусто» фиксируется для этой даты.
- При перезапуске можно догнать сегодняшний неотправленный дайджест после
  DIGEST_TIME. Прошлые календарные даты не рассылаются.
- Длинный дайджест разбивается на части; каждая имеет отдельную запись outbox
  и подтверждение отправки. Уже подтверждённые части повторно не планируются.
- При перепривязке чата ожидающие части старой привязки отменяются. Уже
  отправленный сегодня дайджест не дублируется автоматически в новом чате.
- Ссылка на задание открывает личный диалог с ботом; сервис повторно проверяет
  членство перед показом данных.

### Повторы и ограничения доставки

- Outbox хранится в SQLite. У записи — уникальный event_key, status,
  next_attempt_at, attempts, lease_token и lease_until.
- Lease — 2 минуты. Захватывается одна запись; подтверждение требует того же
  токена. Просроченный обработчик не может подтвердить чужой новый захват.
- Максимум 5 попыток, задержки между ними 15/30/60/120 секунд; retry_after Telegram
  имеет приоритет, если он больше. После лимита — failed с диагностическим кодом.
- 403 на личной отправке помечает недоступность личного чата и прекращает
  дальнейшие отправки до нового личного обращения пользователя.
- Ограничение скорости общее для интерактивных и фоновых отправок:
  до 20 сообщений/секунду суммарно, не чаще одного сообщения/секунду в личный
  чат и одного сообщения за 3,1 секунды в группу. Ожидание отменяется context.
- Дедупликация предотвращает повторное планирование и отправку подтверждённых
  записей. При аварии между принятием сообщения Telegram и записью результата
  в SQLite возможен дубль: гарантии exactly-once Telegram Bot API не даёт.

## Изменения схемы

Существующий 0001_identity.sql не изменяется. Добавляются новые миграции
0002_learning и 0003_notifications. Каждая содержит Up/Down; Down выполняется
только в проверках временных БД, не на пользовательских данных.

| Объект | Согласуемые поля/изменения |
| --- | --- |
| groups | Добавить telegram_chat_id NULL UNIQUE, digest_enabled DEFAULT true, version DEFAULT 1, chat_binding_version DEFAULT 0; последняя увеличивается только при привязке/перепривязке чата |
| users | Добавить private_chat_available DEFAULT false; текущее group_id и role сохраняются |
| subjects | id, group_id FK, name, teacher NULL, archived_at NULL, version, created_at, updated_at; уникальное активное имя в группе и UNIQUE(id, group_id) |
| assignments | id, group_id FK, subject_id, kind, title, description, deadline_at, importance, url NULL, created_by FK users, status, version, created_at, updated_at; составной FK(subject_id, group_id) |
| attachments | id, assignment_id FK, kind document/photo, file_id, file_name, mime; индекс assignment_id |
| completions | user_id FK, assignment_id FK, done_at; PK(user_id, assignment_id) |
| reminders | id, assignment_id FK, user_id FK, assignment_version, source default/snooze, offset_seconds NULL, send_at, sent_at NULL, cancelled_at NULL; уникальная стандартная плановая запись на пользователя/задание/version/интервал |
| settings | user_id FK, key, value; PK(user_id, key); ключи reminders_enabled, quiet_start, quiet_end |
| dialog_states | id AUTOINCREMENT, user_id FK, kind, step, payload_json, revision, status active/completed/cancelled/expired, expires_at, updated_at; уникальный user_id только для status=active, индекс expires_at |
| digest_runs | id, group_id FK, local_date, binding_version, status, created_at; UNIQUE(group_id, local_date) |
| outbox | id, event_key UNIQUE, kind reminder/digest, reminder_id NULL FK, digest_run_id NULL FK, group_id FK, user_id NULL FK, part, payload_json, status, attempts, next_attempt_at, expires_at, lease_token NULL, lease_until NULL, sent_at NULL, telegram_message_id NULL, last_error_code NULL |
| audit_log | id, group_id NULL FK, actor_id NULL FK, action, entity, entity_id, payload_json, at; системный актор NULL |

Все прикладные timestamps — TEXT RFC3339 UTC; local_date — YYYY-MM-DD по TZ.
CHECK ограничивает enum, положительные version/revision и допустимые сочетания
полей outbox. Payload содержит типизированные поля/ID учебных объектов;
сырые Telegram update, токены и коды приглашений в журнал не попадают.
Статусы outbox: pending/processing/sent/skipped/failed/cancelled; повтор снова
использует pending. Статусы digest_runs: planning/queued/sent/empty/partial/failed/cancelled.
Уникальность стандартного reminders применяется к записям без cancelled_at:
это позволяет вновь включить ещё не отправленный будущий интервал.

Аудит фиксирует успешные изменения групп, членства, редакторов, предметов,
заданий, отметок и настроек. Payload — ID и имена изменённых полей; полный текст
переписки или описание задания в журнал не копируются. Отладочные тики не
создают отдельные строки аудита. Текущий bootstrap администраторов не меняется.

Обязательные индексы: users(group_id), subjects(group_id),
assignments(group_id, deadline_at), assignments(subject_id),
reminders(send_at) WHERE sent_at IS NULL AND cancelled_at IS NULL,
reminders(user_id, assignment_id), outbox(status, next_attempt_at),
outbox(lease_until) WHERE status='processing', audit_log(group_id, at).

Новых env-ключей на этом этапе не требуется. Используются существующие TZ,
DIGEST_TIME и REMINDER_OFFSETS. Пример и README уточнят их фактическое действие.

## Порядок реализации

1. Доменные типы, миграции и репозиторные контракты с общей UnitOfWork.
2. Регистрация с вступлением/выходом, группы, привязка чата и права редакторов.
3. Предметы, задания, вложения, отметки, версии и аудит.
4. Устойчивые личные диалоги, router, команды, меню и callback; замена эхо.
5. Личные настройки, планирование напоминаний, digest_runs и outbox.
6. Scheduler, доставка через Telegram adapter, rate limiter и завершение процесса.
7. Документация, новые ADR, проверка целостности после перезапуска и Docker.

## Критерии приёмки

- Через Telegram можно пройти полный цикл: admin создаёт группу и предмет,
  назначает editor; student вступает, editor публикует задание с вложением,
  student видит его и ставит/снимает отметку.
- В текущую группу нельзя получить доступ с ролью или ID другой группы.
- Отложенные/устаревшие кнопки и параллельные изменения не портят данные.
- Диалог переживает перезапуск; истечение TTL обрабатывается понятно.
- Напоминания идут лично; группа получает только дайджест без персональных отметок.
- Проверены перенос дедлайна, отмена, snooze, тихие часы, блокировка бота,
  накопившиеся интервалы, частичный дайджест, retry_after и истёкший lease.
- Тесты с fake clock проверяют даты в TZ и переход календарного дня; тесты
  fake Telegram API не отправляют сообщения реальным пользователям.
- Миграция существующей схемы сохраняет пользователей, роли и даты; Up/Down/Up
  тестируется только на временных БД.
- make test, make test-race, make lint, make build, make docker-check,
  make docker-build проходят; покрытие internal/service не ниже 70%.
- Пользовательский .env и работающий контейнер не изменяются агентом.
  Запуск с реальным токеном, развёртывание и слияние остаются действиями человека.

# Бэкап, обновление и восстановление на сервере

На VPS нужны только Docker и Docker Compose v2. Go, Make и исходники не нужны.
Все команды ниже выполняются **на хосте**, в каталоге с серверными
`docker-compose.yml` и `.env`. Входить внутрь контейнера не требуется.

## 1. Подготовить Compose один раз

Пример серверного файла: [deployment/compose.yaml](deployment/compose.yaml).
Он использует готовый образ из реестра, без `build`.

На уже работающем сервере **сохрани прежний каталог проекта, имя проекта,
имя volume и его подключение к `/data`**. Добавь в свой Compose сервис `backup`
из примера, подключив к нему тот же volume, что у `bot`, с суффиксом `:ro`.
Не заменяй существующий volume новым из примера: это откроет пустую БД.
Изменение файла само по себе контейнеры не перезапускает.

В примере обе строки `image` читают `BOT_IMAGE` из `.env`. Добавь туда:

```dotenv
# Пример! Укажи реально опубликованный тег с этой реализацией.
BOT_IMAGE=salo1278/nsmu_medical_bot:0.0.1
```

Это переменная Compose. Настройки приложения (`BOT_TOKEN` и остальные)
остаются в том же `.env`; в Docker-образ файл не включается. Старый образ
`0.0.0` не содержит `/app/backup`: для бэкапа нужен образ, собранный после
этого изменения. CI по-прежнему собирает и публикует один Dockerfile;
в образе теперь два бинарника.

Подготовь каталог и проверь файл без запуска:

```bash
mkdir -p backups
docker compose config --quiet
docker compose ps -a
```

Последняя команда должна показывать существующего бота. Если списка нет,
ты находишься в другом каталоге/Compose-проекте — сначала вернись к рабочему.

Сохрани имя прежнего образа и фактическое имя volume:

```bash
BOT_CONTAINER=$(docker compose ps -a -q bot)
docker inspect "$BOT_CONTAINER" --format '{{.Config.Image}}'
docker inspect "$BOT_CONTAINER" --format '{{range .Mounts}}{{if eq .Destination "/data"}}{{.Name}}{{end}}{{end}}'
```

Скопируй эти две строки в свои заметки. Старый тег понадобится для отката.
Инструкция рассчитана на именованный volume, как в проекте; пустое имя
означает другое подключение, которое нужно сохранить в обоих сервисах.

## 2. Сделать резервную копию

**Бот должен быть остановлен всё время копирования.** Утилита архивирует
файлы и не может сама проверить состояние другого контейнера. Другие
процессы также не должны писать в этот volume.

Для первой копии скачай новый образ. Это ещё не запуск и не миграция:

```bash
docker compose pull bot backup
```

Далее выполняй команды **по одной**, проверяя результат каждой:

```bash
docker compose stop bot
docker compose ps -a bot
```

Состояние бота должно быть `Exited`, а не `Up`/`Restarting`. Только затем:

```bash
docker compose run --rm --no-deps backup
```

Успех — строка вида:

```text
Копия создана: /backups/bot-20261031T120000Z-123456.tar.gz
```

На сервере это `./backups/bot-20261031T120000Z-123456.tar.gz`.
Имя будет другим; дальше используй **своё** имя:

```bash
ARCHIVE='bot-20261031T120000Z-123456.tar.gz'
docker compose run --rm --no-deps backup verify --archive "/backups/$ARCHIVE"
sudo ls -lh "backups/$ARCHIVE"
```

`verify` должен написать `Готово: verify`. Он полностью читает архив,
проверяет gzip checksum, состав и безопасные пути; это не SQL-проверка БД.
Внутри находятся `bot.db`, WAL/SHM при наличии и остальные файлы volume.
Ошибки дают ненулевой код; `.partial` — незавершённая копия, её не используй.

Если нужен только бэкап, после успеха верни прежний контейнер:

```bash
docker compose start bot
docker compose logs --tail 50 bot
```

`start` запускает существующий контейнер со старым образом, даже если в Compose
уже указан новый тег. Если бот до копирования был остановлен, оставь его остановленным.

Если копирование или проверка завершились ошибкой — **обновление не запускай**.
Прежний контейнер можно вернуть той же командой `docker compose start bot`.

## 3. Обновить бота после успешной копии

Бот по-прежнему остановлен, копия создана и проверена. Выполни:

```bash
docker compose up -d bot
docker compose logs --tail 100 bot
docker compose ps bot
```

Только сейчас новый бот запускается и применяет миграции. При штатном старте
в журнале появится `app_started`. Проверь `/start` и список заданий в Telegram.
Если контейнер перезапускается или видна ошибка запуска — переходи к восстановлению.

На каждом следующем обновлении: укажи новый опубликованный тег → `pull` →
`stop` → бэкап → `verify` → `up -d bot`. Без успешной копии следующий шаг не выполняй.
Обычный `up -d` не запускает служебный сервис: он находится в профиле `maintenance`.

## 4. Восстановить копию, сохранив текущую БД

Восстановление возвращает состояние **на момент копии**. Более поздние изменения
останутся в прежнем volume. Не запускай старый образ на уже обновлённой БД:
для отката используй пару «прежний тег + копия до обновления».

Сначала останови бота и проверь выбранный архив:

```bash
docker compose stop bot
ARCHIVE='имя-твоего-архива.tar.gz'
docker compose run --rm --no-deps backup verify --archive "/backups/$ARCHIVE"
```

Пока `BOT_IMAGE` указывает на новый образ с утилитой, создай отдельный пустой volume:

```bash
RESTORE_VOLUME="nsmu_bot_restore_$(date -u +%Y%m%dT%H%M%SZ)"
docker volume create "$RESTORE_VOLUME"
docker compose run --rm --no-deps -v "$RESTORE_VOLUME:/restore" backup restore --archive "/backups/$ARCHIVE" --destination /restore
printf '%s\n' "$RESTORE_VOLUME"
```

Успех — `Готово: restore`. Утилита сначала проверяет архив, затем извлекает
его в пустой volume и выставляет владельца `65532:65532`. Непустой каталог
она перезаписывать отказывается. При ошибке восстановления не подключай этот
незавершённый volume: исправь причину и повтори с новым именем.

Скопируй напечатанное имя. Внизу своего Compose замени описание **существующего
ключа** `bot_data` на ссылку на восстановленный volume (пример имени):

```yaml
volumes:
  bot_data:
    external: true
    name: nsmu_bot_restore_20261031T123000Z
```

Если твой ключ назывался иначе, сохрани его название. В сервисах `bot` и `backup`
должен использоваться один ключ. Прежний volume останется нетронутым.

Для отката укажи в `.env` сохранённый **старый тег** `BOT_IMAGE`. Для повторной
попытки обновления оставь новый. После этого:

```bash
docker compose config --quiet
docker compose up -d --force-recreate bot
docker compose logs --tail 100 bot
```

Восстановление выполнено. Проверь `/start` и задания. Старые образы и volumes
не удаляй, пока не убедишься, что бот работает. На образе `0.0.0` служебной
утилиты нет: для следующих бэкапов снова понадобится образ с `/app/backup`.

## 5. Где хранить копии

`./backups` находится на том же сервере: при потере диска можно потерять и БД,
и копии. Скачивай проверенные архивы на другой компьютер или отдельное хранилище.
Файлы содержат данные бота; права по умолчанию — root, `0600`.
Для скачивания обычным серверным пользователем можно передать ему конкретный файл:

```bash
sudo chown "$(id -u):$(id -g)" "backups/$ARCHIVE"
```

Автоматического удаления копий и cron для них нет. Расписание резервного
копирования можно добавить отдельно. `docker compose down -v` и `docker volume prune`
для обновления/восстановления **не нужны**.

## Локально

В корне репозитория используй локальный Compose:

```text
make docker-build
docker compose stop bot
make backup
docker compose start bot
```

Это копия базы **Docker volume**. Файл `./data/bot.db` от `make run` — отдельная
БД и в эту копию не входит. На VPS все операции выполняются Docker-командами
выше, без Make и исходников.

## Если Docker вернул EOF при containers/create

Пример: `error during connect: Post .../containers/create?...: EOF`.
Это обрыв ответа Docker Engine на создание контейнера, до запуска утилиты.
Иногда после него остаётся контейнер в состоянии `Created`; это не готовая копия.

Проверь доступность сервера Docker:

```text
docker version
docker info
```

В `docker version` должен присутствовать раздел `Server`. Когда Engine отвечает,
убедись, что бот остановлен, и повтори команду копирования. После успеха обязательно
проверь созданный архив через `backup verify`, как описано выше. Если EOF повторяется,
перезапусти Docker Desktop через его интерфейс и повтори проверку; перезапуск
затронет другие контейнеры. Обновление бота до успешной копии не выполняй.
